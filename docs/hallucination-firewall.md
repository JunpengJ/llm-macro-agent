# 六层幻觉防火墙设计

> 本文档描述项目中对抗 LLM 幻觉的六层防护体系的设计思路。具体阈值、规则清单、评分参数等核心机密不在本文档范围内。

---

## 一、为什么需要幻觉防火墙

LLM 在自动化分析场景中的幻觉表现，与传统问答场景有本质差异：

| 场景 | 幻觉表现 | 影响 |
|:---|:---|:---|
| **传统问答** | 编造事实、引用虚假来源 | 单次回答错误 |
| **自动化分析** | 编造数据、逻辑跳步、规则误判、方向性颠倒 | **级联污染下游全部输出** |

在自动化分析中，一次幻觉会沿着「简报 → 评分 → 基线 → 次日评估」的链路持续传播，最终导致：
- 基线状态失真
- 次日判断基于错误前提
- 错误累积不可逆

因此，仅靠提示词"请不要编造"远远不够，必须建立**工程化的分层防护体系**。

---

## 二、六层防护的整体结构

```
┌─────────────────────────────────────────────────────────┐
│  第6层：熔断机制（Circuit Breaker）                     │
│  异常时强制降级输出，不产生错误结论                       │
├─────────────────────────────────────────────────────────┤
│  第5层：交叉验证（Cross-Validation）                    │
│  多源信息互相印证，孤立信号不采纳                         │
├─────────────────────────────────────────────────────────┤
│  第4层：规则级校验（Rule-Based Check）                  │
│  触发条件逐项自检，方向性信号不推断为触发                  │
├─────────────────────────────────────────────────────────┤
│  第3层：信源级校验（Source-Level Check）                │
│  分级标注 + 矛盾识别 + 时效核验                          │
├─────────────────────────────────────────────────────────┤
│  第2层：逻辑级校验（Logic Check）                       │
│  方向性常识检查 + 基线一致性检查                         │
├─────────────────────────────────────────────────────────┤
│  第1层：数据级校验（Data Check）                        │
│  与权威快照逐项比对，矛盾以快照为准                       │
└─────────────────────────────────────────────────────────┘
```

**核心原则**：**越底层的防护越刚性，越上层的防护越柔性。** 底层是确定性校验，上层是判断性校验。

## 三、逐层设计

### 第1层：数据级校验（Data Check）

**目标**：拦截"数值编造"和"数值漂移"。

**核心机制**：

- **逐项比对**：将简报中所有关键数值与权威快照逐项比对
- **快照为准**：任何与快照矛盾的数值，一律以快照为准
- **矛盾标注**：矛盾项必须在报告开头明确标注，不得隐去
- **缺失标注**：快照中无对应字段的数据，标注"快照无此数据，待验证"，不得直接引用

**防护边界**：

- 拦截：编造数值、数值篡改、时点混淆
- 不拦截：方向性描述、观点表达

**输出要求**：必须生成核验表格，含"简报值 / 快照值 / 是否一致 / 处置"四列。

---

### 第2层：逻辑级校验（Logic Check）

**目标**：拦截"方向性颠倒"和"基线矛盾"。

**核心机制**：

- **方向性常识检查**：数据方向与基线矛盾时，拒绝采纳
  - 例：基线为"连续增持"，若简报称"暂停"，必须标注矛盾
  - 例：基线为"已知正增长"，若简报称"同比下滑"且无法确认，标注待确认
- **基线一致性检查**：当前快照与基线明显矛盾时，必须基于快照重新评估，不得沿用旧得分
- **时效核验**：判断数据是否已公布，不得将"尚未公布"推断为"未发生"

**防护边界**：

- 拦截：方向性颠倒、时间倒错、基线矛盾
- 不拦截：数据细节的合理差异

**关键设计**：

- 检查项不依赖 LLM 自由判断，而是以**检查清单**形式强制逐项核对
- 检查清单在框架文件中维护，不在提示词中硬编码

---

### 第3层：信源级校验（Source-Level Check）

**目标**：拦截"低质信源被引用"和"矛盾信号被掩盖"。

**核心机制**：

- **分级标准**：每条情报必须标注可信度等级（抽象为 L1-L4）
- **比例约束**：高级别情报占比不得超标，避免"只看数值类、忽略叙事类"
- **矛盾标注**：多源矛盾时并列标注，不裁决
- **时效标注**：超出搜索窗口的信息，标注"背景信息，非本周事件"
- **信源盲区清单**：明确列出"无法在权威信源中验证"的情报

**防护边界**：

- 拦截：低质信源直接进评分、矛盾信号被掩盖、旧闻被当作新闻
- 不拦截：低质信源作为背景参考

**关键设计**：

- 分级不是"取舍"，而是"标注使用方式"
- L3/L4 情报仍然保留，但明确其使用边界

---

### 第4层：规则级校验（Rule-Based Check）

**目标**：拦截"规则误判"和"方向性信号被误当作触发"。

**核心机制**：

- **硬数据优先**：只有满足精确触发条件时才能触发评分，方向性信号不得自行推断
- **逐项自检**：主动扫描所有规则，逐项检查是否满足触发条件
- **清单强制输出**：触发项、未触发项、接近阈值项必须明确列出
- **变化驱动**：无新触发信号时维持基线，不做主观调整

**防护边界**：

- 拦截：方向性信号误判为触发、规则漏检、无依据调整
- 不拦截：符合规则的真实触发

**关键设计**：

- 规则清单在框架文件中维护，提示词只引用不展开
- 规则触发必须可追溯到具体数据点
- 触发依据必须明确列出

---

### 第5层：交叉验证（Cross-Validation）

**目标**：拦截"孤立信号被过度解读"和"单源信息被误用"。

**核心机制**：

- **多源印证**：关键结论必须有多源信息支持
- **孤立信号标注**：单一来源信息标注"待交叉验证"
- **矛盾信号识别**：多源矛盾时，明确标注矛盾点
- **背景约束检查**：与框架背景约束矛盾的信号，必须重新评估

**防护边界**：

- 拦截：单源信息直接进评分、孤立信号被过度解读
- 不拦截：单源信息作为背景参考

**关键设计**：

- 交叉验证不等于"多数票"，而是"多角度印证"
- 矛盾信号不追求统一，而是标注差异

---

### 第6层：熔断机制（Circuit Breaker）

**目标**：在异常情况下强制降级输出，不产生错误结论。

**核心机制**：

- **触发条件**：当某关键数据突破预设的极端阈值时，进入熔断状态
- **熔断期间**：锁定上一有效状态，不做主观调整
- **熔断解除**：仅在满足明确的解除条件后恢复
- **锁定追溯**：熔断的触发时间和持续状态必须记录在基线中

**防护边界**：

- 拦截：极端状态下的主观判断
- 不拦截：正常状态下的规则触发

**关键设计**：

- 熔断是"保护机制"，不是"惩罚机制"
- 熔断期间输出仍然正常，只是评分锁定
- 熔断条件在框架文件中维护，不在提示词中硬编码

## 四、六层防护的协同

### 4.1 防护顺序

```
数据级 → 逻辑级 → 信源级 → 规则级 → 交叉验证 → 熔断
```

**不可跳跃**：前面的层未通过时，后面的层不生效。

### 4.2 拦截优先级

| 优先级 | 层次 | 原因 |
|:---|:---|:---|
| 最高 | 第1层（数据） | 数据错误必然导致结论错误 |
| 次高 | 第6层（熔断） | 极端状态下必须保护 |
| 中 | 第4层（规则） | 规则误判直接影响评分 |
| 低 | 第2/3/5层 | 逻辑/信源/交叉问题可标注但不必强制拦截 |

### 4.3 降级路径

某一层失败时的降级：

| 失败层 | 降级方式 |
|:---|:---|
| 数据级 | 使用快照值，标注矛盾，不采信简报值 |
| 逻辑级 | 维持基线，不做调整 |
| 信源级 | 使用高等级信源，低等级仅作背景 |
| 规则级 | 只记录触发信号，评分不调整 |
| 交叉验证 | 标注单一来源，等待后续验证 |
| 熔断 | 输出"熔断状态"，锁定上一有效状态 |

## 五、关键设计决策

### 决策 1：为什么不是单一的"提示词约束"

**背景**：早期版本依赖提示词"请不要编造数据"，但实际效果差。

**原因**：
- LLM 无法可靠地"自我约束"
- 提示词约束无法覆盖所有幻觉形态
- 提示词越复杂，越容易在长上下文中被忽略

**决策**：将约束从"提示词"转为"工程结构"。

**收益**：约束可靠性从"概率性"提升为"确定性"。

### 决策 2：为什么分层而不是单层

**背景**：单一防护层无法同时处理数据错误、逻辑错误、信源问题、规则误判。

**决策**：分层防护，每层职责单一。

**收益**：便于独立优化、独立测试、独立替换。

### 决策 3：为什么底层刚性、上层柔性

**背景**：如果所有层都刚性，系统会频繁熔断；如果都柔性，防护失效。

**决策**：数据级/熔断层刚性，逻辑级/信源级柔性。

**收益**：在"防幻觉"和"可运行"之间取得平衡。

### 决策 4：为什么矛盾不强制统一

**背景**：多源矛盾时，强制统一会掩盖真实分歧。

**决策**：并列标注，不裁决。

**收益**：下游能看到完整信息，自己做判断。

### 决策 5：为什么保留信源盲区

**背景**：早期简报只列"查到什么"，不列"没查到什么"，导致下游误以为信息完整。

**决策**：强制输出信源盲区清单。

**收益**：下游对信息完整度有准确认知。

## 六、效果与验证

### 6.1 稳定性指标

- 评分波动：长期迭代后稳定在极小区间内
- 状态延续：基线继承后无大幅跳变
- 复现性：相同输入下输出一致

### 6.2 验证方式

- **回归测试**：每次规则更新后，用历史数据回测
- **人工抽查**：对关键结论逐项人工核验
- **基线审计**：定期审计基线是否与快照一致

### 6.3 迭代路径

```
V0.1 → V0.2 → ... → V6.x
（每次迭代解决一类具体幻觉问题）
```

**每次迭代必须解决具体问题**，不做抽象优化。

---

## 七、适用边界

本六层防护体系适用于：

- 自动化分析场景（每日/每周/每月）
- 需要状态延续的场景（动态基线）
- 输出会被下游使用的场景
- 数据源有权威基准的场景

**不适用**：

- 纯对话场景（无权威基准）
- 单次问答场景（无需状态延续）
- 创意生成场景（无对错标准）
